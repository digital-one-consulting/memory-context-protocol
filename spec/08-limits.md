# §8 Limits

A file memory earns trust by what it refuses to promise. These are the failures the protocol
cannot prevent, stated here before anyone else states them. They are the subject of Paper 004.

## 8.1 A note can be loaded and wrong

A memory file states a fact without its evidence chain, and the fact ages while the file does
not. Nothing in the layer verifies a note at read time; the layer's honest offer is a dated
claim, not a current one. A rotted number arrives with the authority of injection — already in
context, phrased with the same confidence as every fact beside it. The working rule: **take
lessons from memory, take numbers from the artefact.** Record the command that measures a
thing in preference to the value it measured.

## 8.2 A transcript restore can be the wrong continuity

A harness that restores the last conversation (`claude --continue`) offers a second
continuity, and both restores succeed silently. It is right for a console recovering from a
reboot and wrong for a session that has run a fortnight — the restore brings back exactly the
accumulation the protocol exists to shed. The memory files are the durable baseline beneath
both; the transcript is never the baseline.

## 8.3 No hook can force the unwritten lesson

The Stop hook can force a dream to run; nothing can force it to be good. Consolidation is the
one phase inside the agent, and a tired operator who lets a summary stand in for a lesson has
satisfied every mechanical check. The budget check turns the most common decay — an index that
became a store — into a printed line. It does not prevent it.

## 8.4 Nothing crosses the project boundary

A per-project memory is per project. What one repository learned about a vendor, a convention
or a mistake does not reach the next repository, and the protocol makes no attempt to carry it.
That is a different artefact — a memory shared across repositories, an organisation and the
models of several vendors — with its own failure modes and its own paper series, *The Second
Layer*: <https://digital1.foundation/articles/the-second-layer/>.

## 8.5 The harness

This specification names Claude Code's events, files and paths because that is where it was
measured. The file format and the index rules do not depend on them; the hook contract's two
roles do not either. Everything else — event names, the instruction file, the auto-memory path,
the slash-command directory — is the harness's, and a port replaces it.
